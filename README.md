# 双版本字幕对齐合并工具（SRT Align & Merge）

导入两份 SRT 字幕，系统按**时间重叠 + 文本相似度**进行顺序对齐，自动识别**一对一、一对多、多对一**片段；界面并排展示候选组与置信度，可逐组选择保留哪一侧的文本与时间轴；**未处理的冲突禁止导出**。合并结果重新编号并通过时间单调性校验后可下载为标准 SRT。

纯前端应用（React + TypeScript + Vite），全部计算在浏览器本地完成，**无需任何外部服务**。

## 一键启动（Docker）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8080**

- 宿主机端口：`8080`（容器内 nginx 监听 `80`，如需修改请调整 `docker-compose.yml` 的 `ports`）
- 停止：`docker compose down`

## 本地开发

要求 Node.js ≥ 18：

```bash
npm install        # 安装依赖
npm run dev        # 开发服务器 → http://localhost:5173
npm test           # 运行核心算法单元测试（vitest）
npm run build      # 类型检查并产出 dist/
npm run preview    # 预览构建产物 → http://localhost:4173
```

## 使用流程

1. **导入**：分别选择/粘贴版本 A 与版本 B 的 SRT 文件（也可点击「载入示例数据」快速体验）。
2. **确认对齐组**：系统自动完成顺序对齐并分组展示：
   - 每组标注类型（1:1 / 1:N / N:1 / 仅 A / 仅 B）与置信度（时间重叠 45% + 文本相似度 55%）；
   - 置信度 ≥ 65% 的组自动按默认方案确认（文本取 A、时间轴取并集）；
   - 置信度 < 65% 的组标记为**冲突（待处理）**，必须人工选择后才能导出；
   - 每组可独立选择：保留文本（A / B / 两者都保留）、时间轴（A / B / 并集）。
3. **校验并导出**：
   - 存在未处理冲突时，下载按钮禁用；
   - 导出前校验时间轴单调性（开始时间不减、结束大于开始、相邻不重叠），可一键自动修复；
   - 导出结果按时间排序并从 1 重新编号，下载为 `merged.srt`（UTF-8 带 BOM）。

## 对齐算法说明

- **评分**：每组得分 = `0.45 × 时间区间IoU + 0.55 × 文本相似度 − 0.04 × 组内多余条数`。
  - 文本相似度 = 字符二元组 Dice 系数与归一化 Levenshtein 的均值（归一化时去除 HTML/ASS 标签与标点，中英文均适用）。
- **求解**：动态规划求全局最优顺序对齐，转移包括 1:1、1:k、k:1（k ≤ 3）以及单侧跳过（惩罚 −0.3，用于容纳仅单侧存在的字幕）。
- **复杂度**：时间 O(n·m·K)，单个文件数千条字幕可秒级完成；超过约 3000×3000 规模会提示分批处理。

## 目录结构

```
├── Dockerfile             # 多阶段构建：node 构建 → nginx 托管
├── docker-compose.yml     # 一键启动，映射 8080 → 80
├── nginx.conf             # 静态托管 + SPA 回退
├── index.html
└── src/
    ├── lib/
    │   ├── srt.ts         # SRT 解析 / 序列化（重新编号）
    │   ├── similarity.ts  # 文本归一化与相似度
    │   ├── align.ts       # 动态规划顺序对齐（1:1 / 1:N / N:1 / 单侧）
    │   └── merge.ts       # 取舍应用、单调性校验、自动修复
    ├── components/        # 导入面板、统计条、对齐组卡片、导出面板
    └── App.tsx            # 状态编排：文件 → 对齐 → 取舍 → 导出
```
